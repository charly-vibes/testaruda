# Stress-Test Pipeline & Import Validation

**Last updated:** 2026-07-27

This document describes the stress-test and import validation toolchain for
testaruda's language adapters, including results across all managed languages.

---

## Overview

testaruda has three stress-testing and validation tools:

| Tool | Language | Purpose |
|------|----------|---------|
| [`select-commits.sh`](../scripts/select-commits.sh) | Agnostic | Mine git history for candidate commits |
| [`stress-test.sh`](../scripts/stress-test.sh) | Agnostic | Run full adapter pipeline against a repo |
| [`validate-imports.py`](../scripts/validate-imports.py) | Multi | Compare adapter import parsing vs AST ground truth |

These tools form a pipeline: pick commits → run adapter → validate accuracy.

---

## 1. `select-commits.sh` — Git History Mining

Selects commits suitable for stress testing based on configurable criteria.

```bash
# Basic usage
./scripts/select-commits.sh /path/to/repo

# Filter by type and count
./scripts/select-commits.sh --types bugfix,mixed --sample 10 --format json .
```

**Options:** `--min-files`, `--max-files`, `--sample`, `--types` (source, test, mixed, bugfix), `--since`, `--format` (json or text)

**Output:** JSON with commit hash, message, changed files, categorized file lists (source/test/config), and commit type.

---

## 2. `stress-test.sh` — Adapter Pipeline

Runs all 6 adapter commands against a repo and reports structured results.

```bash
# Python adapter (default)
./scripts/stress-test.sh --base HEAD~5 --head HEAD /path/to/repo

# Rust adapter
./scripts/stress-test.sh --adapter testaruda-adapter-rust /path/to/repo

# Julia adapter (requires --test-dir for per-repo discovery)
./scripts/stress-test.sh --adapter testaruda-adapter-julia \
  --test-dir /path/to/repo/test /path/to/repo
```

**Pipeline phases:**

| Phase | Command | What it measures |
|-------|---------|-----------------|
| 1 | handshake | Protocol version, capabilities, response time |
| 2 | discover | Test count, file paths, discovery time |
| 3 | fingerprint | Files hashed, hashing time |
| 4 | static-deps | Changed files, edges created, unresolved |
| 5 | run-args | Selected count, args generation time |
| 6 | ingest | Simulated test output parsing |

**Options:** `--base`, `--head`, `--sample`, `--adapter`, `--test-dir`, `--timeout`, `--output`

---

## 3. `validate-imports.py` — Import Parsing Validation

Compares each adapter's import detection against a ground-truth extracted via
the language's own parser (AST, `use`-statement parser, etc.).

```bash
# Auto-detect language from repo
./scripts/validate-imports.py /path/to/repo

# Specify language
./scripts/validate-imports.py --language rust .
./scripts/validate-imports.py --language julia /path/to/julia-project

# List supported languages
./scripts/validate-imports.py --list-languages

# Run all available test repos
./scripts/validate-imports.py --all
```

**Supported languages:**

| Language | Backend | Ground truth method | Adapter |
|----------|---------|-------------------|---------|
| Python | `PythonBackend` | `ast` module | `testaruda-adapter-python` |
| Rust | `RustBackend` | `use`-statement parser | `testaruda-adapter-rust` |
| Julia | `JuliaBackend` | `import`/`using` parser | `testaruda-adapter-julia` |
| TypeScript | `TypeScriptBackend` | `import`/`require` regex | `testaruda-adapter-typescript`* |
| Clojure | `ClojureBackend` | `:require`/`:import` parser | `testaruda-adapter-clojure`* |

*\* Adapter not yet built — tracked in testaruda-xq1, testaruda-4tm*

---

## End-to-End Pipeline

The three tools can be chained together:

```bash
# 1. Pick interesting commits
COMMITS=$(./scripts/select-commits.sh --sample 3 --types mixed --format json .)

# 2. Run stress-test on each
echo "$COMMITS" | python3 -c "
import json, subprocess
data = json.load(sys.stdin)
for c in data['commits']:
    h = c['hash']
    subprocess.run(['./scripts/stress-test.sh',
        '--base', h + '^', '--head', h, '--sample', '5', '.'])
"

# 3. Validate import accuracy
./scripts/validate-imports.py --language rust .
```

## Adapter Compatibility Notes

### Python Adapter
- Scans cwd for `test_*.py` and `*_test.py` files
- Import parser handles absolute, relative (`.` and `..`), and lazy imports
- Does NOT handle imports in comments or strings (may produce false positives)
- Uses regex-based line parsing for static-deps

### Rust Adapter
- Requires `cargo test --no-run` for test discovery
- Handles `use crate::...` and `use std::...` patterns
- Skips std/core/crate/internal deps
- Uses tree-sitter queries for static-deps

### Julia Adapter
- Discovers `@testitem` blocks only (ReTestItems.jl, not standard `Test.jl`)
- Default discover path is Testimonial.jl's own `test/` directory
- Requires `--test-dir` to scan other repositories
- Static-deps returns "unresolved" without prior ingest
- Ingest requires a real Julia runtime for coverage recording

### TypeScript & Clojure Adapters
- Not yet built (tracked in testaruda-xq1, testaruda-4tm)
- Validation backends exist in `validate-imports.py` as stubs
- Candidate repos documented in `docs/`
